# github-watcher

Telegram-бот, который следит за GitHub-аккаунтом и присылает уведомления о внешней активности: просмотры репозиториев, источники переходов, звёзды, форки, подписки, чужие issues и pull requests.

GitHub хранит статистику трафика только 14 дней — бот сохраняет её в SQLite и копит историю бессрочно.

## Что отслеживается

| Событие | Источник (GitHub REST API) | Уведомление |
|---|---|---|
| Просмотры и уникальные посетители | `traffic/views` | прирост с прошлого прохода |
| Источники переходов | `traffic/popular/referrers` | новый источник; 🔥 для hh.ru, kwork, habr, t.me, linkedin |
| Клоны | `traffic/clones` | только в статистике (в основном это боты) |
| Звёзды | `repos/{repo}` → `stargazers_count` | +1 / −1 и сколько всего |
| Форки | `forks` | кто форкнул |
| Подписчики репозитория | `repos/{repo}` → `subscribers_count` | изменение количества |
| Подписчики профиля | `users/{user}/followers` | новые и ушедшие |
| Issues и PR от других людей | `issues` | новые |
| Новые репозитории | `user/repos` | автоматически берутся под контроль |

Кто именно открывал страницу, ставил звезду или подписывался на репозиторий, GitHub не сообщает никому, даже владельцу: списки звёзд и подписчиков закрыты (REST отвечает 403/404, GraphQL отдаёт пустой список при ненулевом счётчике). Поэтому по ним бот следит за количеством. Имена доступны только у форков, подписчиков профиля и авторов issues/PR.

## Как устроено

- Один процесс: бот на **aiogram 3** и фоновый цикл опроса раз в час (`POLL_INTERVAL`).
- Новые репозитории подхватываются автоматически, удалённые или ставшие приватными — снимаются с контроля (с уведомлением).
- Запросы к GitHub асинхронные (**httpx**), репозитории опрашиваются параллельно с ограничением `asyncio.Semaphore`.
- **SQLite**: дедупликация на уровне базы — `PRIMARY KEY` + `INSERT ... ON CONFLICT`, а не проверки в коде.
- Первый проход по каждому репозиторию — «базовый»: текущее состояние запоминается молча, уведомлений о старых звёздах и просмотрах не будет.
- Ошибка в одном репозитории (и даже в одном запросе) не теряет остальные данные; одинаковая ошибка приходит в Telegram один раз.
- Всё новое пишется в журнал событий с датой — он показывается в отчётах.
- Один fine-grained токен, только на чтение.
- Бот отвечает только владельцу (`TG_ADMIN_ID`).

```
app/
  config.py      настройки из переменных окружения
  github.py      клиент GitHub REST API (только чтение)
  db.py          SQLite: трафик, источники, звёзды/форки/подписки, issues
  watcher.py     проход: опрос API → сравнение с базой → события
  views.py       тексты уведомлений
  report.py      полный отчёт: стартовый и недельный
  dashboard.py   кнопка «Текущий отчёт» и карточки репозиториев
  main.py        бот + фоновый цикл + недельная сводка
  healthcheck.py проверка для Docker
tests/           pytest, GitHub подменяется через httpx.MockTransport
```

## Интерфейс в Telegram

- Кнопка **«📊 Текущий отчёт»** внизу чата — сводка по всем репозиториям за 14 дней: просмотры и уникальные, клоны, звёзды, форки. Репозитории с новыми событиями отмечены 🆕, а над кнопками — список нового с прошлого просмотра с датами.
- Под сводкой — кнопки с именами репозиториев: **карточка репо** с разбивкой по дням (просмотры, уникальные, клоны за 30 дней), источниками переходов, популярными страницами, количеством звёзд и подписчиков, списком форков и журналом событий.

## Команды бота

- `/now` — то же, что кнопка «Текущий отчёт»
- `/check` — проверить сейчас
- `/stats [дней]` — просмотры по репозиториям (по умолчанию 30 дней)
- `/week` — сводка за 7 дней
- `/report` — полный отчёт за 7 дней прямо сейчас
- `/sources` — источники переходов

## Расписание

- **Каждый час** — опрос GitHub; в Telegram приходят только изменения (новые просмотры, источники, звёзды, форки, подписки, issues/PR, новые репозитории).
- **Первый запуск** — полный стартовый отчёт по всей доступной истории: трафик за 14 дней (больше GitHub не хранит), текущие звёзды, форки, подписчики, источники и популярные страницы.
- **Воскресенье, 20:00** — полный отчёт за неделю: просмотры, клоны, источники, всё новое за 7 дней.

## Запуск

1. Создать fine-grained токен GitHub: доступ ко всем репозиториям, права только на чтение — **Administration** (нужно для Traffic API), Metadata, Issues, Pull requests.
2. Создать бота у @BotFather.
3. `cp .env.example .env` и заполнить.

Локально:

```bash
pip install -r requirements-dev.txt
pytest
python -m app.main
```

На сервере:

```bash
docker compose up -d --build
docker compose logs -f
```
